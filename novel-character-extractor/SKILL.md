# 从原著提取角色人物档案（省 token 优先）

把一部长篇原著变成一个角色的结构化档案。**成本优先级高于质量**：预设预算是"一次模型读入 ≤12 万字 + 一次成档输出"，所有超出预算的需求靠收窄摘录解决，而不是靠多读。

本技能的 scripts/ 目录下有 4 个脚本（相对本技能目录调用），它们承担了全部机械工作，零 LLM 成本。

## 产物

`人物档案/<角色名>.md`，结构固定如下（名场面与三观是核心，规则见第 5 步）：

```markdown
# <角色名>（原名/外文名）
## 人物速览        ← 一段话 + 要点列表（身份/职位变迁/家庭/主要人际）
## 外貌            ← 综合描写 + 3~6 条带出处引文，注明跨卷/跨章变化
## 性格            ← 按"面"分小节，每面 2-4 句概括 + 1 条精要引文
## 三观：世界观·人生观·价值观
### 世界观 / ### 人生观 / ### 价值观
                   ← 每节按观点分条：观点标题 + 2~3 句概括 + 引文 + 出处
## 爱好与特长      ← 列表，尽量带出处
## 说话风格        ← 口癖/称呼/语气特征 + 4~8 条代表性原句引文
## 背景与经历      ← 家庭背景 + 按卷序的重大事件时间线
## 性格名场面（核心章节）
                   ← 按"面"分组小标题；每组 ≤2 个代表片段；
                     每片段 = 3-5 句情节概述 + 较长逐字引文 + 出处（第X卷·章节名）
## 备注            ← 覆盖范围、译名差异、引文错字照录说明
```

## 流程（严格按序执行）

### 0. 确认输入

从用户请求里收集三件事（**用户已说清的直接执行，不要回头追问**，只补缺失项）：
1. 原著路径（epub / txt / 文件夹均可）；
2. 角色名及**已知别名/译名变体**。变体是最大的坑：同一译本里同一角色可能写作"佑巳"也可能写作"祐巳"。用户只给一个写法时，第 2 步用姓氏计数交叉验证；
3. 输出目录（默认 `人物档案/`）。

工作目录默认 `_charwork/`（src/ 源文本、excerpts.md 摘录、notes.md 笔记）。

### 1. 预处理（零 LLM 成本）

```bash
python <技能目录>/scripts/prepare.py <原著路径> _charwork/src
```

epub 按 spine 顺序抽纯文本，txt 自动猜编码（UTF-8→GB18030→Big5→UTF-16，坏字节容错替换）。
**跑完必须抽查一个输出文件的开头**（用 Read 看 30 行），确认不是乱码再继续；是乱码就换编码参数重转，不要带病前进。

### 2. 密度侦察（零 LLM 成本）

```bash
python <技能目录>/scripts/scan.py _charwork/src 名字 变体1 变体2
```

据密度表分三层（决定第 3 步参数）：
- **T0 主场卷**（计数显著高于其他卷）：这些卷里角色以代词出场而不带名字的段落最多，要靠整章收录补偿；
- **T1 中等**：窗口摘录；
- **T2 零星**（全书合计 <30 次）：窗口摘录甚至跳过，并在档案备注里声明"该角色在 X 卷基本未登场"。

同时验证变体：计数为 0 的变体弃用；**若姓氏出现次数远多于名字合计，必有未发现的变体**——试形近字/简繁/异体（如 祐↔佑、莉↔丽）再扫一次。

### 3. 摘录（零 LLM 成本，核心省 token 步骤）

分两轮跑（第二轮按需）：

```bash
# 第一轮：全书总览摘录（total-cap 自动按体量比例分摊预算，段级超限会截断保留头部）
python <技能目录>/scripts/excerpt.py _charwork/src _charwork/excerpts.md \
    --names 名1,名2 --before 20 --after 20 --chapter-full 8 --total-cap 120000

# 第二轮（仅对 T0 主场卷）：全量补跑并追加合并（--files 不受 total-cap 挤压）
python <技能目录>/scripts/excerpt.py _charwork/src _charwork/excerpts.md \
    --names 名1,名2 --files 22,23 --per-file-cap 80000 --append
```

- 脚本会打印"摘录 X 字 / 原文 Y 字 = Z%"和截断提示。**最终 excerpts.md 控制在 ~12 万字内**；超了就调小 before/after、提高 chapter-full、调低 total-cap，而不是全交给模型读；
- 出现"[注] 已按体量比例分摊"时，检查摘录里主场卷是否被截断（搜"已截断"）——被截了就对那些卷跑第二轮 `--files` 补跑（同时可适当调低第一轮的 total-cap，或删掉重来）；
- 想要纯窗口模式（不整章收录）把 `--chapter-full` 设为 999；
- 已知盲区（接受，不补救）：角色仅以"她/姐姐"出场而无名字的段落会漏。整章收录已补偿大半，剩余损失由用户明确的"省 token 优先"背书。

### 4. 精读做笔记（唯一一次大额模型读入）

用 Read 分段读完 `_charwork/excerpts.md`（每次 ≤1200 行，读完为止，不要回读），边读边把素材写入 `_charwork/notes.md`：

- 按模板分类：外貌 / 性格 / 爱好与习惯 / 说话风格 / 背景 / 三观点滴 / 重要场景；
- 每条素材 = 1-2 句场景说明 + **逐字引文** + 【文件·章节】出处；
- 重要场景优先记：有冲突、有转折、能体现人物不同侧面的段落，摘长一点的连续对话；
- 引文必须逐字摘录摘录文件中的原文，不改正一个字（明显的 OCR/翻译错字也照录）。

若摘录文件超过 12 万字且调参空间已用尽，就分两次读完——仍远低于逐卷精读的成本。

### 5. 成档

按"产物"模板写 `人物档案/<角色名>.md`。两条核心规则：
- **名场面按"面"分组**：角色的不同侧面必须全覆盖（宁滥毋缺），但**同一侧面的相似场面最多选 2 个最有代表性的**——这是删减冗余、控制篇幅的主要手段；
- **三观每条观点必须配引文**：没有原文支撑的观点不写；素材不足的维度如实写"原著中体现较少"，不编造。

### 6. 引文校验（零 LLM 成本）

```bash
python <技能目录>/scripts/verify_quotes.py 人物档案/<角色名>.md _charwork/src
```

判读零命中清单：
- 标 `[注释?]`（说明/依据/译名/（ 开头）→ 编辑性注释，忽略；
- 标 `[需核对]` → 逐条到原文 grep 核实：确属漏字/改写就修正档案；原文本来如此（源文本错字）则照录并加（原文如此）注记。

校验器对"弯引号 vs 直引号、全角 vs 半角标点、用……拼接多段"已做归一化兼容，零命中通常就是真问题。

## 引文铁律

1. 引文逐字照录，一字不改、不新编；源文本错字照录，必要时在引文后加（原文如此）；注意不要顺手删掉原文里的脚注号（如"①"）等杂讯，删了就不算逐字；
2. 每条引文标出处（第X卷/文件·章节名）；源文件没有 `#` 章节标题时标到卷名/文件名为止；
3. 概述与分析用自己的话写，不与引文混排；转述性内容不要放进 blockquote；
4. 校验不通过的引文：要么修正为逐字，要么降级为非引用的概述。

## 成本参考（实测基线）

对一部 ~200 万字、37 卷的长篇、单个重要角色（全书 2900+ 次名字命中）：
- 逐卷派 agent 全读的旧做法：单角色 200 万+ subagent token；
- 本流程实测：摘录 8~13 万字（覆盖原文 3~5%）→ 模型读入约 13 万字，连笔记与成档的推理开销合计约 150~200 万 subagent token 量级中主要是推理，纯读入只占 ~1/10；规模较小的书按比例更省。
产出质量的主要损失点：代词场景遗漏、零星卷覆盖不足、被截断的段落——均在"省 token 优先"的接受范围内。用户若要求补全，对指定卷 `--files` 重跑摘录再做增量笔记即可。
