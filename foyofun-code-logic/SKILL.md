# logic 层开发（foyofun-code-logic）

## 设计背景

logic 层是数据的骨架：接收 → 存储 → 加工 → 提供接口 → 派发事件。
好的 logic 模块让 UI 层"傻瓜式调用"：拿快照就能展示，不需要理解业务规则。

**本 skill 的核心增量是独立闭环**：UI/美术/后台任一方未就绪时，logic 也能独立完成
并用假数据自测通过——集成期只填充自己拥有的契约桩，不改别人代码。

标准文件结构见 `references/structure-lua.md`（Lua 参考实现 + C#/C++ 适配说明），
新建文件一律按它生成分区；骨架阶段由 foyofun-code-stub 按它生成。

## 职责边界

✅ 负责：协议收发与解析、数据存储缓存、业务规则计算、数据加工（转成 UI 可用形状）、
对外防御性接口、数据变更事件派发、与界面无关的定时任务。

❌ 不负责：控件操作、界面布局动画、任何 UI 内部逻辑。
logic 可触发**系统级 UI**（弹窗/飘字/确认框），但只 Show，不触碰其内部。

## 执行流程

### 阶段 0：规模判断

改动 ≤ 30 行 && ≤ 2 文件 && 不新增文件 → **轻量路径**：
读目标函数上下文 + foyofun-code-api 快查 + 直接改 + foyofun-code-review 轻量自检。
否则走完整流程。

### 阶段 1-4：调研 → 风格 → 经验 → Plan

1. 调研（foyofun-code-research，强制——不拿调研结论不进 Plan）
2. 已有模块加风格分析（foyofun-code-style）；新模块跳过
3. 加载经验库（foyofun-code-experience）
4. 按 foyofun-code-plan 模板输出方案；跨 UI 对接的任务**必须写契约段**
   （快照形状/意图清单/事件清单），不确定点列出来等用户回答

### 阶段 5：骨架（foyofun-code-stub）

按标准结构生成；跨层对接点打 `[SEAM]`，闭环假数据打 `[MOCK]`。等用户确认。

### 阶段 6：实现

持续参考：风格摘要、经验条目、API 积累（每个 API 调用前经 foyofun-code-api 验证）。
实现规则（通用思想，语言无关）：

- **防御性门面**：对外接口内部做好兜底（无数据返回空值结构而非 nil/报错），
  不让调用方阻塞在防御代码上
- **懒加工 + 脏标记**：原始数据落地只置脏；getter 发现脏且被需要时才加工。
  **性能瓶颈出现之前不缓存**——缓存是优化，不是默认
- **key 映射缓存**：带 uid 之类的数据按 key 映射缓存，避免数据争抢
- **发送接口 Ensure 形态**（按需）：同一请求有多个触发源时，发送处做在途去重 + TTL；
  单一触发源不必加。UI 永远不直接发协议
- **数据先落地、后派发**：先更新缓存再 PostEvent，订阅者收到事件即可读到新数据；
  注意**禁止事件自激励环**（请求事件与响应事件不同名）
- **状态声明与重置合一**：DefineAndReset 模式，重连/登出直接复用
- **接口三分类**：原子（最小不可拆）/ 门面（对外，内部兜底）/ 编排（内部流程，
  平级调用不嵌套）——写函数前先想清楚它是哪类

### 阶段 7：闭环测试（本 skill 的核心要求）

不依赖后台与 UI，在本层内验证数据流：

- **协议直连**：临时绕过网络层，send 后直接调用 on_xxx_rsp 喂构造的假应答
  （假应答打 `[MOCK]` 标记），验证"发送 → 接收 → 落地 → 派发"全链
- **加工正确性**：脏标记触发加工、快照字段组装、防御分支（无数据/脏数据）返回值
- **定时/事件链**：logic 持有的定时器（如消息扫描）用日志验证触发与收敛
- **重置语义**：调用 DefineAndReset 后状态归零，无残留

闭环通过的标准：数据流每一步在日志里可见、防御分支被真实执行过一次。

### 阶段 8：自检（foyofun-code-review）

重点：API 全部走项目封装；关键路径有日志；事件注册注销成对
（框架是否兜底看项目适配表，不兜底的项目必须手写注销）。

### 阶段 9：收尾

向用户报告：`[SEAM]`/`[MOCK]` 标记清单（集成期的对接点）、
新发现的 API 建议收录、值得沉淀的新经验建议记录。

## 关键原则

1. **数据流 > 文件列表**——从数据视角理解任务
2. **如非必要勿增接口**——在现有接口里补逻辑是默认选项
3. **反投机**——不预埋接口、不过早缓存、不提前抽象
4. **闭环先行**——等待外部依赖不是停止的理由
5. **日志给未来的自己**——关键节点不省，循环内不滥
