# ui 层开发（foyofun-code-ui）

## 设计背景

UI 层是玩家直接感知的层：接收数据 → 绑定控件 → 响应交互 → 更新展示。
它调用 logic 层接口拿数据，自己不持有业务规则。

**本 skill 的核心增量是独立闭环**：logic/协议未就绪时，UI 用假数据与可编排的假时序
独立开发并自测全部交互——集成期只替换假数据源和绑定事件，不改渲染代码。

标准文件结构见 `references/structure-lua.md`（Lua 参考实现 + 其他语言适配说明），
新建文件一律按它生成分区；骨架阶段由 foyofun-code-stub 按它生成。

## 职责边界

✅ 负责：控件绑定、事件注册与注销、交互响应、数据到控件刷新、UI 状态管理（页签/显隐）、
动画、异步防御（界面关闭后回调不执行）、呈现级时序（倒计时、过渡动画）、
需求只存在于界面打开期间的定时刷新（如实时排行榜）。

❌ 不负责：业务规则（发现自己写 `if level >= 10 and vip...` 就停下，这属于 logic）、
协议收发、数据存储管理、布局与美术资源（蓝图/预制体的事）。

## 执行流程

### 阶段 0：规模判断

改动 ≤ 30 行 && ≤ 2 文件 && 不新增文件 → **轻量路径**：
读目标函数上下文 + foyofun-code-api 快查 + 直接改 + foyofun-code-review 轻量自检。
否则走完整流程。

### 阶段 1-4：调研 → 风格 → 经验 → Plan

1. 调研（foyofun-code-research）：logic 层可用接口、相似 UI 参考、资源存在性
2. 已有 UI 模块加风格分析（foyofun-code-style）；新模块跳过
3. 加载经验库（foyofun-code-experience），重点 naming/abstraction 分类
4. 按 foyofun-code-plan 输出方案：**控件清单**（从蓝图已有控件出发）、
   **数据来源**（哪个 logic 接口/快照）、**交互流程**（点击 → 发生什么）、
   契约段（快照形状/意图清单）；不确定点等用户回答

### 阶段 5：骨架（foyofun-code-stub）

跨层对接点打 `[SEAM]`，假数据源打 `[MOCK]`。等用户确认。

### 阶段 6：实现

实现规则（通用思想，语言无关）：

- **只认快照**：UI 读数据只经快照/intent 接口，不摸 logic 内部状态；
  `self.datas` 只在两处写——初始化时的同步获取、事件回调里的重拉；Update* 只读
- **意图分发**：交互先发意图（调 Ensure 型接口或 dispatch），呈现反馈（置灰、倒计时）就地做
- **三层刷新按成本选**：InitUI（一次性）/ UpdateUI（全量，含 SetData）/
  Refresh（低成本触发控件内部刷新）——SetData 成本高的控件不要反复全量喂
- **Update\* 三步式**：获取数据 → 防御性编程 → 组件刷新，每个刷新函数形状一致
- **注册注销成对**：事件、定时器一律成对出现。框架是否兜底**看项目适配表**——
  兜底的项目可以省注销代码，但设计上仍要知道谁负责清理；不兜底的项目必须手写
- **打开期请求放 OnShow**（不是 OnPostInitialized）：界面可重复 Show 时每次进入
  都要刷新数据；请求由 logic 层 Ensure 去重，重进不会造成请求风暴
- **生命周期定时器**：界面打开期才需要的定时器（实时轮询）归 UI，
  OnClose 清理；与界面无关的归 logic
- **异步防御**：任何异步回调（网络、定时器、动画完成）执行前检查界面是否已销毁
- **禁止事件自激励环**：订阅的变更事件处理中不得再触发同一数据的请求链

### 阶段 7：闭环测试（本 skill 的核心要求）

不依赖 logic 与后台，UI 内部自测：

- **假数据源接口化**：数据获取集中在 `[MOCK]` 标记的函数/数据源后面，
  渲染代码只面向快照形状写，不知道背后是真是假
- **时序可编排**：假源要能模拟分次到达、延迟、失败、空数据——验证 loading 态、
  部分数据态、就绪跳变、失败态、空列表占位都真实渲染过
- **交互全链路**：每个按钮/页签/列表项点击可走完"意图发出 + 呈现反馈"，
  闭环期意图可以只打日志（集成期接真）
- **聚合器真实现**：一个视图依赖多个数据源时（如资源依赖多个包下载），
  "轮询+收敛"的聚合逻辑**真实实现**，只把它查询的数据源换成假的；
  事件加速 + 轮询对账是缺省组合
- **清理验证**：关闭界面后定时器停、无悬挂回调（日志或断点确认）

### 阶段 8：自检（foyofun-code-review）

UI 侧重：注册注销成对、异步回调有防御、Update* 无业务规则混入、
每帧/滚动回调内无全量日志。

### 阶段 9：收尾

同 logic：报告 `[SEAM]`/`[MOCK]` 清单、API 收录建议、经验沉淀建议。

## 关键原则

1. **UI 不实现业务规则**——规则永远在 logic，UI 只呈现
2. **闭环先行**——等 logic 不是停止的理由，渲染代码面向快照形状写
3. **假的只是数据源**——时序编排和聚合逻辑必须是真的
4. **注册注销成对、异步必须防御**——UI 层两大经典 bug 源
5. **刷新成本分层**——Init/Update/Refresh 各司其职
