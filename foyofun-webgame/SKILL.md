# 网页小游戏协作开发流程

与主人一起把一个（通常很模糊的）游戏想法做成可部署、可由其他 AI 接手的网页游戏。
按五个阶段推进，**每阶段以 2 轮对话为硬目标**；每阶段结束必须有凝固产物（定案文档 / 冻结设计 / 可玩闭环 / 修复清单 / 远程仓库）。

角色分工是固定的：**主人是设计者与验收者，AI 是提议者与实现者**。AI 的职责不只是实现——主人常给模糊想法，你要主动补全他没想到但合理的设计，并把他的设计理念翻译成可落地的机制。

## 阶段一：需求确认（≤2 轮对话）

主人可能只给一句话（例如"我想做一个名称大乱斗"）。你的任务是把这句话补全成可落地的完整需求。

**第一轮输出**（一次给全，让主人只需确认或否决）：
1. **三问定锚**：玩法核心循环是什么（玩家做什么、看什么）、给谁玩在什么场合（决定部署规模与账号体系）、"好玩"的标准是什么（主人的设计理念，务必逐条记录）；
2. **问题清单**：把所有待定决策列成编号清单，**每条附默认建议**——主人喜欢直接采纳默认值，不要让他做开放式问答；
3. **主动提议**：主人没想到但合理的设计要大方提（房间观战、排行榜、性格系统、数据池、职业系统……这些都源自提议并被采纳）；
4. **理念转机制**：主人的理念类要求（如"属性不代表强弱""没有废角色""要有节目效果"）必须当场给出具体机制方案（预算制+补偿层+克制、保底必得、可调概率旋钮）让他确认，不能只口头答应。

**第二轮**：定案摘要 + 遗留小项（仍带默认值）。到此需求冻结，凝固进设计文档。

## 阶段二：设计框架（≤2 轮对话）

**第一轮**给出完整框架，至少包含：
1. **技术选型**：用一个统领性原则推导，不要罗列选项让主人挑（例：战斗引擎需要前后端共享 → 全栈 TypeScript monorepo，其他选型全部服从这条）；
2. **架构图**（ASCII 即可）+ 目录结构；
3. **核心扩展点的接口**（模组契约、能力文件格式等）——主人明确要求内容可拓展，扩展点是设计重点；
4. **数据模型**与**核心机制公式草案**；
5. **分期计划**：每期有验收标准，第一期必须是可玩闭环。

**第二轮**：吸收主人的补充修改（他会认真审框架并改设定，例如模组与模式合并、性格不得废人），更新后**冻结设计**。

冻结纪律：设计文档中每条决策带编号、日期与理由；分歧点写明"默认值，待主人复核"；之后新决策只追加日志、不悄悄推翻；文档是唯一权威来源，接手者只读它。

## 阶段三：动手实现

主人确认后按冻结计划实施，先引擎后界面，自测通过才算交付。

实现顺序与要点：
1. **引擎先行**：核心逻辑做成确定性纯函数（同输入同输出），随机只用种子驱动的 PRNG，禁止 Math.random——可测试、可回放、可批量模拟的根基；
2. **内容数据化**：技能/能力一个文件一个、数值全部进数据表，主人会持续低成本修改；
3. **服务器做薄**：只做身份、存储、裁判、广播；
4. **前端最后**：样式收敛到主题层（主人会换风格），移动端竖屏优先；
5. **自测清单**（全部通过才算完）：单元测试、批量模拟（含镜像对称 ≈50% 的对称性检查）、构建通过、浏览器实测（桌面 + 手机视口走完整用户路径）。

实现期的技术踩坑清单（依赖、Vue、并发、缓存等具体案例与规避方法）见 [references/pitfalls.md](references/pitfalls.md)。**动手前先读一遍**，多数坑是可以提前绕开的。

## 阶段四：测试调优（≤2 轮对话）

主人会实测并报 bug 或提调优需求（常是体验语言，如"更有节目效果"）。处理纪律：

1. **先定位层再动手**：报"数值对不上/行为怪"时，先写不变量诊断脚本扫描机制层（如：每次扣血后记录值 = 前值 − 伤害），用数据证明机制干净，再查表现层；
2. **验证必须能在旧 bug 存在时失败**，否则是假阳性（HMR 错乱、页面跑旧代码都会造成假阳性——验证前先干净重启）；
3. **体验语言翻译成显式参数**：如"更有节目效果" → 集火概率 / AI 轮盘赌 / 顺序抖动三个旋钮进公式表，主人可继续调；
4. 主人的设计原则若有普适性（如"性格不得废人"），落成代码级自检（乘数越界直接抛错）并记入决策日志；
5. 逐条回应主人的每一条反馈，全部落地后总结。

## 阶段五：完工交付

主人说"可以了"之后：

1. **部署能力落地**：单进程托管前端构建产物 + API（一个端口全包），验证 `curl /` 返回页面再写进文档；
2. **README**：介绍与玩法、快速开始、部署步骤、**定制指南**（加技能/加数值表/加模组分别改哪个文件，带代码模板）、常见问题——让主人自己就能改内容；
3. **设计文档**：决策日志完整（编号+日期+理由+教训），让任何 AI 或人只读文档即可接手；
4. **敏感信息扫描**后推送远程仓库（检查密码/密钥/用户路径/用户数据文件是否被 gitignore 覆盖）。

## 通用纪律（所有阶段）

- 修 bug 先定位层，用数据证明，再动手；修复不得引入新问题，验证不得是假阳性；
- 全局单例 + 可重入异步循环必须带代次取消；按文本缓存的解析结果不得内嵌"每场会重置的标识符"；
- keep-alive 页面缓存会让 onMounted 失效、组件状态跨路由残留——所有页面级初始化与复位都要复查；
- 每完成一个阶段，把新决策与教训写进设计文档的决策日志——这是给未来接手者最贵的礼物。
