# 实现期踩坑案例库

每个案例：现象 → 根因 → 规避。全部来自真实项目实录。动手前通读，遇到同类现象直接对号入座。

## 依赖与环境

### 原生依赖构建脚本被 pnpm 拦截
- **现象**：`pnpm install` 后 `require('better-sqlite3')` 报 "Could not locate the bindings file"。
- **根因**：新版 pnpm 默认拦截依赖的安装脚本；且配置位置随版本变化——v10 在 `package.json` 的 `pnpm.onlyBuiltDependencies`，v11 已迁移到 `pnpm-workspace.yaml`（`allowBuilds` 或 `onlyBuiltDependencies`）。放错位置静默无效。
- **规避**：装完原生依赖立刻写一行最小代码验证能加载；构建允许清单直接放 `pnpm-workspace.yaml`。prebuild 下载失败时可手动 `npx prebuild-install -r node -t <node版本>`。

### CLI 参数里的 `--`
- **现象**：`pnpm sim -- A B --vs C D` 中字面量 `--` 被 pnpm 透传进 argv，被解析成队伍成员。
- **规避**：参数解析器显式跳过孤立的 `--`；用数据校验这类问题（镜像对局不对称就是它暴露的）。

### 操作系统差异
- Windows Git Bash：`curl -d` 发中文会编码错乱（用 UTF-8 文件 + `--data-binary` 或 urllib）；终端中文乱码是显示问题，JSON 实为正常 UTF-8。

## Vue / 前端

### keep-alive 三连坑（高发！）
页面组件被 `<keep-alive>` 缓存后：
1. **onMounted 只在首次执行**——页面初始化（开新对局、拉数据）必须改由 `onActivated` + `watch(route)` 共同驱动；
2. **组件状态跨路由残留**——loading/busy 等一次性标志在切走后不复位，按钮永远 disabled；激活钩子里复位所有一次性状态；
3. **deactivated 组件的 watcher 仍然活跃**——全局 route watch 会在组件不可见时触发，逻辑要检查路由匹配。
- **总规避**：给 router-view 加 keep-alive 后，把所有依赖 onMounted 的页面初始化逐一复查；同路径"恢复"与"重开"的语义要显式区分（用路径 nonce 区分同名连打）。

### 可重入异步循环必须带代次取消
- **现象**：快速连开两场战斗，血条来来回回、飘字数字与掉血对不上、两场战报内容混在一起。
- **根因**：全局单例播放器的 `play()` 无取消机制，旧循环未结束时新循环再开，两份事件流交错应用同一状态。
- **修复**：类内加 `runId`，`play()` 开头 `const myRun = ++this.runId`，循环内每个检查点（含每次 await 之后）比对，不一致即 return。
- **二次坑**：第一版修复把 `runId++` 也写进了 `reset()`，而 `play()` 的顺序是 `++runId → reset() → 检查`——**每个新 play 一开局就误杀自己**，保护从未生效。`reset` 只清状态，代次只由 `play` 递增。

### 按文本缓存不得内嵌"每场重置的标识符"
- **现象**：连打两场，第二场战报里出现第一场的人名。
- **根因**：战报渲染按行文本缓存解析结果，而两场行文本完全相同（uid 每场都从 A-1 编号），缓存命中了旧解析——里面固化了旧名字。
- **规避**：缓存只存稳定标识（uid），名字/阵营等"随场次变的量"推迟到渲染时查询。推广：任何 memo 键里含会重置的 id 时同理。

### Vue Boolean prop 未传时是 false 不是 undefined
- **现象**：可选布尔 prop 不传，`v-if="prop !== false"` 恒为假，组件整块不渲染且无报错。
- **规避**：可选布尔 prop 一律 `withDefaults(defineProps<...>(), { prop: true })`。

### rAF 在不可见窗格被暂停
- **现象**：聊天窗格/后台标签页里，依赖 requestAnimationFrame 的自动滚动静默失效。
- **规避**：需要在任何可见性下都生效的逻辑，用 MutationObserver 回调里直接读 `scrollHeight`（强制同步布局，值准确）并同步赋值 scrollTop。贴底滚动还要带"用户上翻即暂停跟随"的 stick 判定。

### HMR 导致的验证假阳性
- **现象**：改了多处文件后测试"通过"，实际页面跑在旧代码或热更污染状态上；后续又测出修过的 bug"复发"。
- **规避**：涉及核心模块（状态单例、全局循环）的修改，验证前强制 `reload` 或重启 dev server（`--force` 清缓存）；修并发类 bug 的验证用例必须**能在旧 bug 存在时失败**，否则验证无效。

### 结构变更要全局搜引用
- **现象**：日志从字符串数组改成对象数组后，复制战报功能 join 出 `[object Object]`。
- **规避**：改共享数据结构时，grep 全部消费点逐一更新。

## 后端

### 无 body 请求带 content-type
- **现象**：DELETE 请求 400 "Body cannot be empty when content-type is set to 'application/json'"。
- **根因**：前端 fetch 封装对所有请求统一设 `content-type: application/json`，DELETE 无 body 时 Fastify 拒绝。
- **规避**：封装层仅在确有 body 时设置 content-type。

### 校验要分层
- **现象**：建队接口误用"整场战斗校验"（要求双方队伍齐备），建一支队永远报错。
- **规避**：单实体校验（`validateTeam`）与业务级校验（`validateTeams`）分开，创建走前者、开战走后者。

### 数据快照要自足
- **现象**：PVE 战报历史里敌方名字空白。
- **根因**：落库的配置里敌方一侧是空数组，实体由规则层在运行时注入。
- **规避**：落库快照要含展示所需的全部信息（可只存名字占位，运行时仍按 id 重建数值），并区分"展示快照"与"运行时重建"。

### 路由/权限的重复导航细节
- vue-router push 到相同 fullPath 不会触发任何导航事件——"再开一场"类需求需要在路径里掺时间戳 nonce 区分。
- keep-alive 页面上"回跳"类需求则相反：同路径应恢复而非重开。两者语义相反，都要显式实现。

## 机制与数值

### 机制层可疑时先跑不变量扫描
- **做法**：给核心循环写不变量诊断脚本（例：每次伤害事件后 记录hp = 前值 − 伤害、死亡钳制到 0、治疗同理），批量跑几百场统计。主人报"数值对不上"时，先用数据证明机制干净，再查表现层——避免在正确的代码里瞎找。
- **注意**：不变量要考虑合法特例（击杀溢出时血量钳到 0 是正常的）。

### 平衡与对称性
- 批量模拟时先跑**镜像对局**（同名同队互打），胜率应 ≈50%——不对称说明有先手方偏差或解析 bug。
- "节目效果"类体验需求翻译成显式参数：集火概率（targetFocusBias）、AI 前 K 名轮盘赌（aiTopK）、行动顺序抖动（roundJitter），全部进公式表。

### 设计原则落成代码自检
- 主人的设计原则若可程序化（如"性格乘数必须落在 [0.7,1.4]，任何性格不禁用行为类别"），写成模块加载时的断言，违反直接抛错——防止未来新增内容违反铁律。

### 确定性引擎的红利（一开始就要做对）
- 战斗 = `simulate(配置, 种子) → 事件流` 的纯函数：回放/历史只需存配置+种子（客户端本地重算）、服务器天然免疫作弊、批量模拟验平衡零成本、镜像对局对称性可测。
- 事件流是前后端唯一协议；事件携带表现描述（纯数据），客户端是通用解释器——换皮不用改引擎。
